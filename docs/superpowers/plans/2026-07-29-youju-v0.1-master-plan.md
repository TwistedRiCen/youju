# 有据 V0.1 Master Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement milestone plans task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 交付一个移动端优先、本地优先、无AI也可完整使用，并支持用户自备密钥AI辅助的网购退款纠纷材料整理工具。

**Architecture:** 使用pnpm TypeScript monorepo。Web/PWA在浏览器本地保存事件和原始材料；无状态Fastify API只提供健康检查、规则版本和可选AI临时转发。确定性领域逻辑、规则、AI契约、文件存储和导出能力按包隔离，AI只能产生需要用户确认的候选内容。

**Tech Stack:** Node.js 24 LTS, pnpm 10.34.0, TypeScript strict, Vue 3, Vite 8, Fastify 5, @sinclair/typebox 0.x LTS / JSON Schema, Vitest, Playwright, IndexedDB, OPFS, Web Crypto API.

## Global Constraints

- V0.1只支持“网购商品存在问题且商家拒绝退款”。
- 原始材料默认保存在用户设备，不默认上传业务服务器。
- 无AI路径必须完整可用。
- API Key默认只保存在当前会话内存。
- 未确认AI候选不得进入正式输出。
- 服务端不得保存事件、材料、事实、时间线或API Key。
- 不生成法律结论、赔偿金额、胜诉率或自动投诉。
- 年度基础服务成本目标不超过人民币2000元。
- 所有真实模型调用排除在自动化测试和CI之外。

## Plan Decomposition

该规格包含本地文件系统、领域规则、文档导出、AI转发和公开部署等多个可独立审查子系统，因此分成以下实施计划：

1. `2026-07-29-youju-m1-foundation-plan.md`：仓库骨架、契约、规则、黄金案例、Web/API外壳、CI；
2. M2计划：本地证据存储与无AI完整闭环；
3. M3计划：BYOK AI、副驾驶审核流和AI评测；
4. M4计划：公开演示、PWA、隐私说明和部署；
5. M5计划：自愿反馈与真实使用验证。

只有当前里程碑设计与计划审阅通过后，才编写并执行下一个里程碑的详细计划。

## Milestone Exit Gates

### M1 Foundation

- 根级质量门禁可在干净环境运行；
- 领域、规则和AI契约可运行时校验；
- 黄金案例1可重复验证；
- Web/API外壳可启动；
- CI通过。

### M2 No-AI Core

- 用户无需注册创建事件；
- 本地导入并保留原始文件；
- SHA-256可核验；
- 手工分类、事实、时间线、规则检查和事实陈述可用；
- PDF/ZIP符合规格；
- 删除流程可验证。

### M3 BYOK AI

- OpenAI-compatible接口可配置；
- API Key不持久化；
- AI输出通过Schema；
- 来源关联与用户确认完整；
- 错误与取消不破坏数据；
- AI关闭后继续手工流程。

### M4 Public Demo

- 国内网络可直接访问；
- 无注册、无AI完成演示；
- PWA基础离线壳可用；
- 隐私与AI发送预览清晰；
- 安全响应头和运维手册完成。

### M5 Validation

- 10名用户完成测试；
- 至少3次材料包导出；
- 用户能独立理解流程；
- 没有依赖维护者逐个人工咨询；
- 形成是否扩展第二场景的书面结论。

## Required Review Gates

每个里程碑均执行：

1. 计划审阅；
2. 逐任务TDD实现；
3. 每任务代码审查；
4. 里程碑完整验证；
5. 对照设计规格逐条检查；
6. 威胁模型复查；
7. 用户确认后进入下一里程碑。
