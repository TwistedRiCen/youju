# 有据（YouJu）V0.1 产品与技术设计规格

- 文档状态：已批准设计
- 版本：V0.1
- 日期：2026-07-29
- 首发场景：网购商品存在问题且商家拒绝退款
- 产品形态：移动端优先 Web/PWA
- 核心路线：确定性证据核心 + 可选 BYOK AI

---

## 1. 项目定义

### 1.1 一句话定位

有据是一款面向中国普通用户的关键事件材料整理工具。它帮助用户保存原始材料、建立事件时间线、识别材料缺口，并生成可提交、可打印、可长期保存的事实与材料包。

### 1.2 首版解决的问题

用户在网购退款纠纷中通常拥有订单截图、支付记录、聊天截图、商品照片和物流信息，但缺少统一整理方法，容易出现：

- 原始材料分散；
- 时间顺序不清；
- 关键材料遗漏；
- 事实说明表达混乱；
- 提交材料命名和顺序不统一；
- AI或人工整理结果无法回溯到原始来源。

V0.1 只解决“整理与表达”问题，不处理法律判断、自动维权或结果预测。

### 1.3 产品价值

用户第一次完成流程后，应立即获得：

1. 一份经过确认的事件时间线；
2. 一份证据材料清单；
3. 一份缺失材料提醒；
4. 一份事实陈述；
5. 一份可导出的 PDF/ZIP 材料包。

## 2. 设计原则

### 2.1 证据优先

所有正式输出必须来自：

- 用户手工填写并确认的信息；
- 用户确认过的 AI 提取结果；
- 确定性规则引擎的检查结果。

未经用户确认的 AI 内容不得进入正式材料包。

### 2.2 AI 可选

没有 API Key、模型余额不足、模型不可用或用户拒绝使用 AI 时，核心流程仍须完整可用。

### 2.3 本地优先

原始文件默认保存在用户设备，不默认上传业务服务器。服务端只承担官网、规则更新、版本信息和可选 AI 临时转发等轻量职责。

### 2.4 最小化收集

基础功能不强制：

- 注册账号；
- 绑定手机号；
- 实名认证；
- 上传身份证；
- 上传家庭住址；
- 云端保存原始材料。

### 2.5 事实与判断分离

系统可以整理“发生了什么”，但不判断：

- 商家是否违法；
- 用户是否一定有权退款；
- 应赔偿多少；
- 投诉是否会成功；
- 某一材料是否具有最终法律效力。

### 2.6 所有 AI 结果可追溯

每个 AI 提取字段必须记录：

- 来源文件；
- 来源页码或区域；
- 提取时间；
- 使用模型；
- 模型输出版本；
- 置信状态；
- 用户确认状态。

## 3. V0.1 范围

### 3.1 支持场景

仅支持：

> 用户通过网购平台购买商品，收到商品后发现质量、破损、描述不符等问题，商家拒绝退款或未妥善处理。

### 3.2 支持材料类型

V0.1 支持：

- JPG、JPEG、PNG、WebP；
- PDF；
- 用户手工文本记录。

V0.1 暂不支持：

- 视频内容分析；
- 音频内容分析；
- 压缩包递归解析；
- 聊天记录自动从微信导入；
- 平台账号授权抓取订单；
- 短信自动读取。

### 3.3 支持的材料分类

- 订单信息；
- 支付凭证；
- 商品宣传或详情页；
- 商品问题照片；
- 商家沟通记录；
- 退款或售后记录；
- 物流与快递信息；
- 发票或合同；
- 用户补充说明；
- 其他材料。

### 3.4 明确不做

V0.1 不包含：

- 法律咨询；
- 法律条文自动适用；
- 赔偿计算；
- 胜诉率或投诉成功率预测；
- 自动代写威胁性、攻击性内容；
- 自动发送投诉；
- 自动登录第三方平台；
- 商家曝光、评分或黑名单；
- 用户社区；
- 公开案例库；
- 多租户机构后台；
- 商业会员体系；
- 云端长期保存原始材料。

## 4. 用户流程

### 4.1 主流程

1. 用户打开产品首页；
2. 选择“网购退款纠纷”；
3. 阅读隐私与使用边界；
4. 创建本地事件；
5. 填写订单基础信息；
6. 上传材料；
7. 手工分类或启用 AI 分类；
8. AI 提取事实候选项；
9. 用户逐项确认、修改或拒绝；
10. 系统生成时间线草稿；
11. 用户确认时间线；
12. 规则引擎检查材料缺口；
13. 用户填写期望处理结果；
14. 系统生成事实陈述草稿；
15. 用户确认最终文稿；
16. 导出 PDF 和 ZIP；
17. 用户可删除本地事件。

### 4.2 无 AI 路径

未启用 AI 时：

- 文件由用户手工分类；
- 订单金额、时间、商家等字段由用户手工填写；
- 时间线由用户手工添加；
- 缺失材料由规则引擎检查；
- 事实陈述由模板生成。

无 AI 路径必须达到可公开使用标准，不得是残缺体验。

### 4.3 AI 路径

启用 AI 后，AI只能：

- 建议材料分类；
- 提取日期、金额、订单号、商家、商品名称等；
- 提取聊天中的事件节点；
- 生成时间线候选项；
- 根据已确认事实生成陈述草稿；
- 提供补充材料提醒。

AI不得直接：

- 修改正式事实；
- 删除原始材料；
- 覆盖用户确认内容；
- 生成法律结论；
- 自动提交材料；
- 自动联络商家或监管部门。

## 7. AI 设计

### 7.1 BYOK 模式

V0.1 允许用户提供自己的 API Key。

支持：

- OpenAI-compatible API；
- 自定义 Base URL；
- 自定义模型名；
- 临时 API Key；
- 连接测试；
- 单次任务成本提示；
- 随时停用 AI。

### 7.2 API Key 策略

默认策略：

- API Key只保存在当前会话内存；
- 页面关闭或刷新后清除；
- 不写入数据库；
- 不写入 localStorage；
- 不写入日志；
- 不进入错误追踪平台；
- 不进入前端统计事件。

可选本地保存能力不进入 V0.1 首发范围。

### 7.3 AI 调用模式

推荐两种实现方式并保留统一接口：

#### A. 临时服务端转发

适用于普通 Web 版。

要求：

- 请求体中 API Key仅用于当前请求；
- 网关和应用日志必须脱敏；
- 禁止记录完整请求体；
- 响应返回后立即释放；
- 设置严格超时和请求大小限制；
- 禁止将密钥用于重试队列或异步任务。

#### B. 桌面端直连

作为后续版本。使用系统安全存储保存密钥，材料和模型请求由用户设备直接处理。

### 7.4 AI Provider 接口

```typescript
interface AiProvider {
  testConnection(config: ProviderConfig): Promise<TestConnectionResult>
  classifyEvidence(request: ClassifyEvidenceRequest): Promise<ClassifyEvidenceResult>
  extractFacts(request: ExtractFactsRequest): Promise<ExtractFactsResult>
  buildTimeline(request: BuildTimelineRequest): Promise<BuildTimelineResult>
  suggestMissingMaterials(request: MissingMaterialRequest): Promise<MissingMaterialResult>
  draftStatement(request: DraftStatementRequest): Promise<DraftStatementResult>
}
```

### 7.5 结构化输出

所有 AI 结果必须通过 JSON Schema 校验。

校验失败时：

1. 不写入领域数据；
2. 可执行一次结构修复请求；
3. 再次失败则终止本次 AI 任务；
4. 向用户展示可理解的失败原因；
5. 保留无 AI 手工路径。

### 7.6 AI 数据最小化

每次调用只发送任务必需信息。

示例：

- 分类图片时，不发送事件全部材料；
- 生成陈述时，只发送已确认事实，不发送未确认候选项；
- 缺失材料检查优先由规则引擎完成；
- 无关聊天内容不得发送；
- 用户可在发送前预览即将提交给模型的内容。

### 7.7 AI 失败降级

必须覆盖：

- API Key错误；
- 余额不足；
- 模型不存在；
- Base URL不可达；
- 超时；
- 限流；
- 内容过长；
- 图片不支持；
- JSON不符合Schema；
- 模型返回空内容；
- 用户中止请求。

所有失败不得破坏原始材料或已确认事实。

## 8. 规则引擎

### 8.1 规则职责

规则引擎负责：

- 检查必填事实；
- 检查建议材料；
- 提示原始载体保存；
- 提醒截图不要裁剪关键上下文；
- 检查金额、时间和主体是否缺失；
- 检查事件说明是否存在未确认事实；
- 检查导出前是否存在冲突项。

### 8.2 规则格式

规则采用 YAML 或 JSON，必须版本化。

```yaml
id: consumer.ecommerce.refund.basic
version: 1.0.0
scenario: ecommerce_refund
requiredFacts:
  - purchase_time
  - merchant_name
  - product_name
  - paid_amount
  - problem_description
  - requested_resolution
recommendedEvidence:
  - order_record
  - payment_record
  - product_issue_photo
  - merchant_communication
warnings:
  - preserve_original_files
  - preserve_original_device
  - avoid_editing_original_screenshots
```

### 8.3 规则来源

每条规则必须保存：

- 来源说明；
- 适用范围；
- 是否属于稳定规则；
- 最近核验日期；
- 维护者；
- 版本变更记录。

V0.1 只采用长期稳定的整理方法，不内置频繁变化的地方政策结论。

## 9. 本地存储与数据安全

### 9.1 存储方案

优先采用：

- IndexedDB 保存结构化数据；
- OPFS 保存原始文件；
- Web Crypto API 计算 SHA-256；
- 本地导出 ZIP 作为用户备份。

### 9.2 原始材料保护

系统导入文件后：

- 计算摘要；
- 保存原始文件副本；
- 不对原文件进行覆盖编辑；
- 脱敏和标注生成新副本；
- 所有导出材料引用原始文件ID；
- 允许用户核验摘要。

### 9.3 删除机制

用户删除事件时必须：

- 删除结构化事件数据；
- 删除 OPFS 文件；
- 删除 AI 分析缓存；
- 删除生成的临时文件；
- 展示删除结果；
- 不保留业务服务器副本。

### 9.4 数据备份

V0.1 支持加密或未加密的本地导出包。默认导出前提示用户：材料可能包含敏感个人信息，应妥善保存。

云同步不进入 V0.1。

## 10. 导出设计

### 10.1 PDF 内容

PDF 至少包含：

1. 封面；
2. 使用边界说明；
3. 事件基本信息；
4. 事实陈述；
5. 事件时间线；
6. 证据清单；
7. 缺失材料提醒；
8. 文件摘要校验表；
9. 生成时间与应用版本。

### 10.2 ZIP 目录

```text
有据_事件材料包_YYYYMMDD_HHmm/
├── 01_事件说明.pdf
├── 02_事件时间线.pdf
├── 03_证据材料清单.pdf
├── 04_材料摘要校验表.csv
├── 05_附件索引.html
└── 06_原始材料/
```

### 10.3 导出前校验

存在以下情况时必须阻止正式导出或要求用户明确确认：

- 仍有未确认 AI 事实被正文引用；
- 存在未解决的时间或金额冲突；
- 缺少事件主体；
- 缺少用户期望结果；
- 原始材料文件丢失；
- PDF生成失败；
- 摘要校验异常。

## 11. 隐私与合规边界

### 11.1 产品声明

产品必须明确说明：

- 有据不是律师事务所；
- 有据不提供法律意见；
- 有据不保证投诉或协商结果；
- AI结果可能出错，必须由用户确认；
- 文件摘要不等于司法鉴定或公证；
- 用户应保存原始设备和原始文件；
- 涉及重大权益时应咨询专业机构。

### 11.2 敏感内容

V0.1 不主动识别或收集：

- 身份证；
- 银行卡；
- 人脸信息；
- 儿童信息；
- 医疗信息；
- 精确住址。

但用户上传材料中可能包含上述内容，因此必须提供：

- 风险提示；
- 脱敏副本工具的后续扩展接口；
- 导出前敏感信息检查；
- 保留原件与脱敏副本分离机制。

### 11.3 AI 数据提示

启用 AI 前必须提示：

- 哪些文件或文本将发送给模型服务商；
- API Key由用户提供；
- 模型服务商可能依据其条款处理数据；
- 用户可不启用 AI；
- 用户可在发送前取消选择材料。

## 12. 威胁模型

### 12.1 主要风险

- API Key泄露；
- 原始材料被上传或记录；
- 日志包含敏感内容；
- XSS读取本地数据；
- 恶意依赖窃取密钥；
- 文件解析漏洞；
- 超大文件导致浏览器崩溃；
- PDF或图片携带恶意内容；
- AI提示注入影响分析结果；
- 导出材料被错误关联；
- 用户误把AI草稿当正式结论。

### 12.2 基础控制

- 严格 CSP；
- 禁止不必要的第三方脚本；
- 依赖锁定与完整性检查；
- API Key不持久化；
- 日志脱敏；
- 文件类型和大小限制；
- 解析过程隔离；
- AI输入视为不可信数据；
- 结构化输出校验；
- 用户确认门槛；
- 明确区分草稿与正式内容；
- 导出前完整性检查。

- 首版可采用轻量 TypeScript 服务，或使用 Spring Boot 3；
- 只承担 AI 临时转发、规则版本和基础健康检查；
- 不保存用户事件和原始文件。

### 13.3 服务端边界

V0.1 服务端不得：

- 保存原始材料；
- 保存用户事实；
- 保存时间线；
- 保存 API Key；
- 建立用户画像；
- 对材料进行异步排队处理；
- 将用户数据用于模型训练。

## 16. V0.1 验收标准

### 16.1 功能验收

必须满足：

- 用户无需注册即可创建事件；
- 能上传并本地保存支持的文件；
- 每个文件生成 SHA-256；
- 用户能手工分类材料；
- 用户能手工创建时间线；
- 规则引擎能提示缺失材料；
- 用户能生成事实陈述；
- 用户能导出 PDF 和 ZIP；
- 用户能删除全部本地数据；
- 未配置AI时全部核心功能可用。

### 16.2 AI验收

必须满足：

- 用户可配置 OpenAI-compatible 接口；
- API Key默认不持久化；
- AI返回结果通过Schema校验；
- 每个事实候选项关联来源；
- 未确认事实不能进入正式输出；
- AI失败后可继续手工完成；
- AI不得生成法律结论；
- 用户可中止AI请求。

### 16.3 安全验收

必须满足：

- 服务端日志不含 API Key；
- 服务端日志不含完整材料内容；
- 原始文件默认不上传业务服务器；
- CSP与依赖安全检查通过；
- 删除流程经过自动化测试；
- 导出包内附件与索引一致；
- 未确认AI内容有明显视觉标识。

### 16.4 体验验收

必须满足：

- 手机端可完成全部流程；
- 首次用户无需阅读长文档即可理解下一步；
- AI与非AI路径均有明确入口；
- 草稿、候选、冲突、已确认状态可辨识；
- 主要操作均有撤销或确认；
- 不使用恐吓、焦虑营销或夸大承诺。

## 18. 成功与停止条件

### 18.1 成功信号

- 用户能够独立完成流程；
- 用户认为时间线和材料包明显有用；
- 无AI用户仍能完成导出；
- AI显著降低手工录入时间；
- 用户愿意推荐给遇到类似问题的人；
- 不需要维护者逐个提供人工咨询；
- 年度基础成本控制在人民币2000元以内。

### 18.2 暂停或调整信号

- 用户普遍拒绝导入材料；
- 用户只需要法律结论，不需要材料整理；
- AI虚构率无法控制；
- 本地存储在主流手机浏览器上不稳定；
- 服务端转发无法满足密钥与隐私要求；
- 大量用户要求自动维权或公开曝光；
- 维护成本明显超过个人可持续范围。

## 19. 开源边界

V0.1 建议采用宽松开源许可证，核心功能长期免费。

开源内容包括：

- Web/PWA；
- 本地证据管理；
- 规则引擎；
- AI Provider接口；
- OpenAI-compatible Provider；
- 导出组件；
- 黄金案例；
- 测试工具；
- 文档。

不得采用：

- 广告驱动；
- 贩卖用户数据；
- 默认上传材料；
