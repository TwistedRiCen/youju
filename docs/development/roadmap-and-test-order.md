# 有据 V0.1 任务拆分与测试顺序

## 1. 实施策略

V0.1 分为五个可独立验收的里程碑。每个里程碑都必须产生可运行、可测试的软件，不允许长时间停留在不可集成的半成品分支。

## 2. 里程碑与任务

### M1：工程底座与黄金案例

目标：证明仓库结构、领域契约、规则格式、AI Schema、案例验证和CI能够协同工作。

任务：

1. 初始化 pnpm workspace 和质量门禁；
2. 创建领域契约；
3. 创建规则 Schema 与基础评估器；
4. 创建 AI 输出 Schema；
5. 创建黄金案例1和验证脚本；
6. 创建 Web/PWA 外壳；
7. 创建无状态 API 外壳与日志脱敏；
8. 建立跨包集成测试和 E2E smoke；
9. 建立 CI 与安全检查；
10. 完成 M1 文档和发布检查。

出口：`pnpm verify` 全绿。

### M2：无 AI 核心闭环

目标：用户无需注册、无需AI即可从创建事件走到材料包导出。

任务：

1. `CaseRepository` 端口与 IndexedDB 实现；
2. `EvidenceBlobStore` 端口与 OPFS 实现；
3. 文件导入、类型检查、数量与大小限制；
4. SHA-256 流式摘要；
5. 事件创建与订单基础信息；
6. 材料列表与手工分类；
7. 手工事实录入与确认；
8. 手工时间线、排序和冲突提示；
9. 规则缺口检查；
10. 模板化事实陈述；
11. 导出前校验；
12. PDF、CSV、HTML和ZIP导出；
13. 事件删除与删除核验；
14. 无AI完整 E2E。

出口：黄金案例1可完全手工完成并导出规定目录结构。

### M3：BYOK AI 副驾驶

目标：AI显著减少录入工作，但不改变证据核心和用户确认门槛。

任务：

1. 会话级 AI 设置与 API Key 生命周期；
2. AI发送内容预览与用户确认；
3. API临时转发、安全日志和请求限制；
4. OpenAI-compatible Provider；
5. 材料分类；
6. 日期、金额、商家、商品和订单号提取；
7. 来源页码/区域关联；
8. FactCandidate 审核工作流；
9. AI时间线候选；
10. AI事实陈述草稿；
11. Schema修复一次重试；
12. 错误码、取消、超时、限流和手工降级；
13. 黄金案例 AI 评测；
14. AI完整 E2E（全部使用mock）。

出口：错误模型输出不能污染正式事实；关闭AI后仍可继续原流程。

### M4：公开演示与部署

目标：国内网络环境中的普通用户可以直接试用。

任务：

1. PWA离线壳与更新提示；
2. 首次使用引导；
3. 隐私、使用边界和AI数据说明；
4. 虚构演示案例一键载入；
5. 异步自愿反馈；
6. CSP、安全响应头和生产构建；
7. 国产浏览器/移动端兼容检查；
8. 静态Web与轻量API部署；
9. 备份、恢复、日志保留和故障手册；
10. GitHub/Gitee发布材料。

出口：公开地址可在不注册、不使用AI的情况下完成演示案例导出。

### M5：真实使用验证

目标：验证实际使用价值，而不是追求Star。

任务：

1. 明确同意的匿名漏斗统计；
2. 完成后单题反馈；
3. 10名测试用户；
4. 至少3次真实导出；
5. 汇总隐私、理解成本和流程中断点；
6. 修复最高优先级问题；
7. 决定是否进入第二场景设计。

出口：形成基于行为和反馈的继续、调整或停止结论。

## 3. 测试实施顺序

测试顺序按“最稳定的纯逻辑 → 浏览器能力 → 外部系统边界 → 完整用户流程”推进。

### 第1层：契约测试

最先建立：

- 领域实体 Schema；
- 枚举和状态约束；
- 规则文件 Schema；
- AI请求/响应 Schema；
- 黄金案例 manifest Schema。

原因：后续包均依赖这些名称、字段和状态值，契约错误越晚发现返工越大。

### 第2层：纯函数单元测试

依次实现：

1. 规则匹配；
2. 必填事实缺失；
3. 推荐材料缺失；
4. 时间线排序；
5. 时间/金额冲突检测；
6. 正式输出过滤未确认事实；
7. 导出命名；
8. 摘要清单生成。

### 第3层：浏览器存储与文件测试

依次验证：

1. IndexedDB结构化记录；
2. OPFS文件写入和读取；
3. 大文件摘要；
4. 刷新恢复；
5. 删除事件；
6. 存储空间不足；
7. 浏览器不支持OPFS时的降级提示。

这类能力必须在真实浏览器引擎中测试，不能完全依赖Node mock。

### 第4层：组件与页面集成测试

依次验证：

1. 创建事件；
2. 上传和分类；
3. 确认事实；
4. 时间线编辑；
5. 规则结果；
6. 陈述编辑；
7. 导出前阻断；
8. 删除确认。

### 第5层：API和安全测试

依次验证：

1. 健康检查；
2. 请求 Schema；
3. API Key日志脱敏；
4. 请求体不落盘；
5. 超时和取消；
6. 上游错误映射；
7. 大小限制；
8. 不允许异步队列和持久化。

### 第6层：AI契约测试

全部使用mock：

1. 合法结构化输出；
2. 非法JSON；
3. Schema不匹配；
4. 一次修复成功；
5. 修复仍失败；
6. 来源缺失；
7. 候选事实冲突；
8. 模型虚构字段；
9. 用户拒绝候选；
10. AI关闭后的手工继续。

### 第7层：端到端测试

先无AI，后AI：

1. 无AI创建到导出；
2. 刷新后继续；
3. 导出包结构；
4. 删除全部数据；
5. AI成功路径；
6. API Key错误；
7. 模型超时；
8. 用户中止；
9. 冲突阻断；
10. 移动端视口与WebKit。

### 第8层：人工兼容与安全检查

每次公开发布前执行：

- Windows Chrome、Edge；
- Android Chrome及至少一种国内厂商浏览器；
- iOS Safari；
- 微信内置浏览器仅做可用性检查，不承诺完整PWA能力；
- CSP、依赖审计、日志抽查；
- 无网络状态；
- 低存储空间；
- 真实手机大图导入性能。

## 4. 回归门禁

每个提交至少运行目标包测试。每个任务结束运行：

```bash
pnpm lint
pnpm typecheck
pnpm test
```

每个里程碑结束运行：

```bash
pnpm verify
```

AI相关任务额外运行：

```bash
pnpm test:ai-contract
pnpm eval:golden-case
```

任何真实模型调用不得进入 CI。
